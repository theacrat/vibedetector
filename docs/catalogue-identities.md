# Editable providers and stable catalogue identities

Providers and models become D1-managed records with generated UUIDs. Display names are editable and never keys. Provider slug is separate from UUID/name, editable with uniqueness and reserved-route validation; default existing slugs remain unchanged. A name-only typo fix cannot break links, deduplication, filters or reports. Models refer to provider UUID and reports refer to provider/model UUID, never names. Graph model filters use UUIDs so renames preserve links.

Provider fields: id, slug, name, maker, status, statusLabel, logo, active, position. Model fields: id, provider (UUID), name, active, position. Archive providers hides their public pages and lists; admin retains them and their models. Archive models hides named public graph access. Provider/model ordering uses stable ID permutations with the same atomic membership guard. Rename changes display fields only. No cascade deletes from admin.

Migration 0004 adds provider table seeded from existing registry with stable UUIDs and rebuilds model/report tables mapping old provider slugs/model names to UUIDs. Keep existing reports, model order/active state and category/timestamps where mapping exists; seed default provider display fields only. No runtime compile-time registry remains. Admin can create/edit/archive/reactivate/order providers and create/rename/archive/reactivate/order models. Validate provider URLs as HTTPS external links and logos as controlled local paths or HTTPS; no script schemes. Slugs reject api/admin/privacy/methodology/robots/sitemap and invalid characters.

Public overview/SSR loads active providers from D1. Resolve public page paths by slug; API UUID lookup may be accepted internally but public routes remain slug-based. Public catalogue/UI parsers validate UUIDs and returned shapes. Generic display-name validation replaces fixed allowlists. Admin authentication/Turnstile/report protections and provider-only anomaly algorithm remain unchanged.
